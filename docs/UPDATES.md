# التحديثات بيني وبين العملاء

كل عميل له مشروع Vercel مستقل (متغيراته وقاعدته ومفاتيحه له)، لكن **كل المشاريع مربوطة بنفس الريبو**. فأي دفع إلى `main` ينشر عند الجميع تلقائيًا.

## أسلّم تحديثًا
1. ادفع إلى `main` (بعد `npx tsc --noEmit` والاختبارات).
2. فيرسل ينشر لكل المشاريع. لا تحتاج شيئًا من العميل.
3. تأكد: `VERCEL_TOKEN=... node scripts/customers.mjs` يعرض كل مشروع وهل هو على آخر نسخة. أضف `--deploy` لإعادة نشر المتأخر.

## أضيف عميلًا
`node scripts/new-customer.mjs --name acme ...` ينشئ المشروع مربوطًا بالريبو الرئيسي.

## عميل نشر بزر «Deploy» (نسخته منفصلة)
يظهر في `customers.mjs` بعبارة `NOT CONNECTED`. اربطه بالريبو الرئيسي:
`node scripts/customers.mjs --relink اسم-المشروع`
ثم تأكد أن Root Directory = `web`. متغيراته وقاعدته ما تتأثر. بعدها يستلم كل تحديث.

## أستلم من العميل
- **أخطاء وملاحظات:** زر «أرسل ملاحظة أو بلاغ خطأ» في لوحته يفتح Issue جاهزًا على الريبو، فيه رقم النسخة وحالة الإعدادات بدون أي مفتاح أو رسائل. يحتاج العميل حساب GitHub.
- **حالة نسخته:** `https://دومين-العميل/api/version` عام ويعرض رقم الإصدار فقط، وتجمعها `customers.mjs`.
- **تعديلات على الكود:** العميل يرفع Pull Request على الريبو (قالب جاهز)، وأنت تراجعه وتدمجه، فيصل للجميع.

## تنبيهات
- خطأ يدفع إلى `main` يصل لكل العملاء. جرّب محليًا، وارجع لآخر commit سليم عبر Revert إذا لزم.
- لا تضع في الريبو أي مفتاح أو بيانات عميل. كل شيء خاص بالعميل يبقى في متغيرات مشروعه.
